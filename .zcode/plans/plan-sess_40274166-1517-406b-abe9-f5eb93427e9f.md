## 目标

仪表盘上的八张外部 CLI 卡片全部可以点击展开，直接读取、编辑并保存该 CLI 在**当前 EasySession 所在机器上的全局配置文件**：

- Claude：JSON
- Codex：TOML（同时修正当前错误的 `config.json` 实现）
- OpenCode：JSON
- Gemini：JSON
- Pi：JSON
- OMP：YAML
- Grok：TOML
- Hermes：YAML

不再把 Gemini、Pi、OMP、Grok、Hermes 点击行为跳转到“可执行文件路径设置”。

## 一、建立统一配置描述与可信路径解析

新增共享的可编辑 CLI 类型和主进程配置 descriptor。每项声明：

- CLI ID；
- 配置格式：`json | toml | yaml`；
- 显示路径；
- 主进程实际路径解析器；
- 是否允许创建不存在的配置；
- 可选的 CLI 动态路径探测方式。

真实路径策略：

- Claude：`~/.claude/settings.json`
- Codex：`~/.codex/config.toml`
- OpenCode：`~/.config/opencode/opencode.json`
- Gemini：`~/.gemini/settings.json`
- Pi：`${PI_CODING_AGENT_DIR || ~/.pi/agent}/settings.json`
- OMP：优先使用配置的 OMP executable 执行 `omp config path`，在返回目录使用 `config.yml`；否则按 `PI_CODING_AGENT_DIR`、`OMP_PROFILE/PI_PROFILE` 和默认 `~/.omp/agent/config.yml` 回退
- Grok：`${GROK_HOME || ~/.grok}/config.toml`
- Hermes：优先执行 `hermes config path`；否则使用 `HERMES_HOME`，Windows 回退 `%LOCALAPPDATA%/hermes/config.yaml`，其他平台回退 `~/.hermes/config.yaml`

Renderer 永远不能提交任意文件路径；只提交 CLI ID，路径由主进程白名单 descriptor 解析。不会把 Hermes 的 `state.db` 或 `.env` 当作配置文件编辑。

## 二、将配置服务升级为原始文本、多格式契约

新增统一 IPC：

- `config:read(cliId)`
- `config:write(cliId, content, expectedRevision?)`

读取返回：

- `cliType`
- `path`
- `format`
- `exists`
- `content`
- `revision`（mtime/size/hash，用于冲突检测）

写入流程：

1. 校验 CLI ID 白名单；
2. 校验 content 是字符串并限制最大尺寸；
3. 根据格式解析验证：
   - JSON：必须为非 null、非数组对象；
   - TOML：使用 TOML parser；
   - YAML：使用安全 YAML parser，拒绝多文档和非法结构；
4. 保存前重新读取 revision，若文件已被其他程序修改则返回冲突，不静默覆盖；
5. 使用现有 `writeFileAtomic()` 写入并保留 `.bak`；
6. 不存在的配置文件允许创建父目录和新文件；
7. 读取错误不再吞成 `{}`，明确区分不存在、权限错误和格式损坏。

保留旧 Claude/Codex/OpenCode IPC 作为兼容包装，但内部转调统一服务；旧 Codex JSON 路径不再作为主配置写入目标，必要时只提示旧文件存在。

## 三、重构 renderer config store

将三份硬编码状态改成按 CLI 键控：

- `documents[cliId]`
- `loaded[cliId]`
- `loadingByCli[cliId]`
- `savingByCli[cliId]`
- `lastSavedByCli[cliId]`

统一方法：

- `loadConfig(cliId, force?)`
- `saveConfig(cliId, content, revision)`
- `invalidateConfig(cliId)`

避免再为每个 CLI 增加一组 API、ref 和 if/else。

## 四、升级 ConfigEditorPanel

让 `ConfigEditorPanel` 支持八种 CLI：

- tabs/标题由共享 CLI 名称和 descriptor 驱动；
- 显示主进程返回的真实路径与格式 badge；
- 编辑器直接显示原始文本，保存后不丢 TOML/YAML 注释和排版；
- JSON/TOML/YAML 分别显示正确的 placeholder 和错误信息；
- 文件不存在时给出最小合法模板：JSON `{}`，TOML/YAML 为空文本；
- 保存、重新加载、错误提示全部统一；
- 有未保存修改时切 tab、重新加载或外部变化必须确认；
- 保存期间禁止重复提交；
- 检测到 revision 冲突时提示“磁盘配置已变化”，提供重新加载而不是覆盖；
- 不显示或编辑凭据文件、`.env`、SQLite 数据库。

## 五、修改仪表盘交互

- `ConfigurableCli` 扩展为八种外部 CLI，直接从可编辑配置描述表派生；
- 八张状态卡都显示配置展开箭头；
- 点击任意卡片展开相同的全宽配置编辑器，并同步 `?panel=<cliId>`；
- 删除后五项跳转路径设置的分支；
- CLI 在线状态与配置文件是否存在分离：即使 CLI 未安装，只要用户需要，也能编辑/创建标准配置文件；
- 保留八卡响应式网格和长路径截断。

## 六、安全与远程边界

本轮仪表盘编辑的是本机全局配置，因为当前 Dashboard 没有实例选择上下文。明确标注“本机配置”。

同时把 API 设计成未来可扩展 `instanceId`，但不在没有目标选择器的情况下猜测远程机器。远程配置编辑后续必须增加独立 capability 和目标实例选择，不能让本地 IPC误写控制端配置并冒充远程成功。

## 七、测试矩阵

新增或更新：

1. 配置 descriptor：八个 CLI 均有正确格式与路径；Windows Hermes、OMP profile、环境变量覆盖。
2. ConfigService：
   - JSON/TOML/YAML 合法写入；
   - 非法格式拒绝且原文件不变；
   - JSON 顶层非对象拒绝；
   - 不存在文件创建；
   - `.bak` 生成；
   - revision 冲突拒绝；
   - 权限/损坏文件返回明确错误。
3. IPC/preload：只接受八个白名单 CLI；拒绝 terminal、任意路径、非字符串和超大内容。
4. Store/组件：八个 tab 加载保存、dirty state、切换确认、reload、保存错误和冲突。
5. Dashboard E2E：
   - 八张卡都有展开箭头；
   - 每张卡点击都能打开对应编辑器；
   - query panel 支持八种 CLI；
   - 后五项不再跳转设置页；
   - 显示实际路径与 JSON/TOML/YAML 格式。
